## Сборка

Gradle запускается на JDK 25: плагин RetroFuturaGradle для 1.7.10 и 1.12.2 собран под Java 25. Java 8 и Java 21 для самих версий мода Gradle находит сам через toolchains.

```bat
set JAVA_HOME=C:\Program Files\Java\jdk-25
gradlew build
```

В PowerShell:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-25'
.\gradlew.bat build
```

Или одной командой из корня репозитория — `build.bat`: он сам ставит JAVA_HOME (другой путь к JDK 25 можно задать переменной `MINEPAPERS_JDK`) и собирает все версии. `build.bat test` вдобавок запускает игровые тесты всех версий, любые другие аргументы уходят в `gradlew` как есть.

Готовые файлы:

```
1.7.10/forge/build/libs/MinePapersOnline-1.7.10-forge-<версия>.jar
1.12.2/forge/build/libs/MinePapersOnline-1.12.2-forge-<версия>.jar
modern/versions/1.20.1-forge/build/libs/MinePapersOnline-1.20.1-forge-<версия>.jar
modern/versions/1.20.1-fabric/build/libs/MinePapersOnline-1.20.1-fabric-<версия>.jar
modern/versions/1.21.1-neoforge/build/libs/MinePapersOnline-1.21.1-neoforge-<версия>.jar
modern/versions/1.21.1-fabric/build/libs/MinePapersOnline-1.21.1-fabric-<версия>.jar
modern/versions/26.1.2-forge/build/libs/MinePapersOnline-26.1.2-forge-<версия>.jar
modern/versions/26.2-forge/build/libs/MinePapersOnline-26.2-forge-<версия>.jar
modern/versions/26.3-forge/build/libs/MinePapersOnline-26.3-forge-<версия>.jar
modern/versions/26.1.2-neoforge/build/libs/MinePapersOnline-26.1.2-neoforge-<версия>.jar
modern/versions/26.2-neoforge/build/libs/MinePapersOnline-26.2-neoforge-<версия>.jar
modern/versions/26.3-neoforge/build/libs/MinePapersOnline-26.3-neoforge-<версия>.jar
```

Для Fabric в папке mods рядом с модом должен лежать Fabric API.

Версия мода задаётся в `gradle.properties` (`mod_version`).

Собрать одну версию:

```bat
gradlew :modern:1.21.1-neoforge:build
```

Только проверить, что всё компилируется:

```bat
gradlew compileJava
```

Запустить игру из среды разработки:

```bat
gradlew :modern:1.21.1-neoforge:runClient
gradlew :modern:1.21.1-fabric:runClient
```

### Тесты

- `gradlew :common:test` (входит в `build`) — тесты общего кода без игры (JUnit, `common/test`): настройки и их ограничения, конфиг, геометрия, сетка картины, окно настройки, обмен картинками.
- `gradlew gameTest` (или `build.bat test`) — игровые тесты: сервер каждой версии и движка (кроме 1.7.10) поднимается сам, прогоняет тесты и выходит с ошибкой, если какой-то упал. Тесты современных версий общие (`modern/src/gametest`), движок только регистрирует их (`src/gametest` узла). У 1.12.2 своего фреймворка игровых тестов нет: те же проверки — в отдельном тестовом моде `1.12.2/forge/src/gametest` (в jar не попадает). Задача `:1.12.2-forge:runGameTestServer` запускает выделенный сервер с плоским миром (`run/gametest`); когда сервер запустился, мод прогоняет проверки и выключает его, при ошибке — с кодом 1.
- `gradlew :1.12.2-forge:runClientScreenshots` — клиент 1.12.2 сам создаёт плоский мир, открывает окно картины в руке, снимает каждую вкладку в `1.12.2/forge/run/screenshots-client/screenshots/` и выходит. В `gameTest` не входит: нужен экран.

```
        forgegradle.gradle  сборка узлов Forge 26.x (ForgeGradle 7)

```

### Подпроекты-версии

Каждая пара "версия Minecraft + загрузчик" — подпроект `<версия>-<загрузчик>` (список — в `settings.gradle`). Версия Minecraft берётся из первой части имени подпроекта, поэтому имя важно.

Старые версии лежат каждая отдельно, в папке `<версия>/<загрузчик>` (1.7.10, 1.12.2).

Современные (1.20+, имена классов Mojang) — одно дерево [Stonecutter](https://stonecutter.kikugie.dev/) в `modern/`: подпроекты `:modern:<версия>-<загрузчик>` в `modern/versions/`. Весь код без загрузчика (только ванильный Minecraft) лежит один раз в `modern/src`; где версии или загрузчики различаются, код размечается условиями в комментариях: `//? if >=1.20.5 {` ... `//?} else {` ... `//?}`, `//? if fabric {`. Для каждого узла Stonecutter сам включает нужную ветку и выключает остальные (комментирует их). В `modern/src` без комментариев лежит код активной версии (`stonecutter.gradle`, в git — `vcsVersion` из `settings.gradle`); другую версию в IDE делает активной задача Stonecutter "Set active project". Код загрузчика (точка входа, регистрация, события, миксины) и его описание мода — в `src` узла, версии зависимостей — в `gradle.properties` узла, сборка — общая на загрузчик: `modern/<загрузчик>.gradle`. Константы для условий — имена загрузчиков `fabric`, `neoforge`, `forge`.

Корневой `build.gradle` для каждого подпроекта:

- подключает `common/java` как дополнительную папку исходников;
- копирует `common/resources` в jar. Для версий до 1.13 папки `textures/block` и `textures/item` переименовываются в `textures/blocks` и `textures/items`;
- кладёт словари из `common/lang` в `assets/minepapers/lang`. Для версий до 1.13 они переводятся в формат `.lang` (см. [Словари](#словари));
- подставляет версию мода и версию Minecraft в `mcmod.info`, `version.properties`, `META-INF/neoforge.mods.toml` и `fabric.mod.json`;
- ужимает библиотеки WebP задачей `shrinkWebp` и кладёт их классы в jar (см. [Общий код и адаптеры](#общий-код-и-адаптеры));
- собирает классы мода без имён локальных переменных (`-g:source,lines`): номера строк в крашрепортах остаются, а jar меньше.

В `build.gradle` самой версии остаётся только её плагин, версия Java и версия загрузчика.

### common/java

Пакет `com.grihail.minepapers`. Здесь только то, что не зависит от версии игры. Код должен собираться на Java 8 и не может обращаться к классам Minecraft и загрузчиков. Можно использовать библиотеки, которые есть во всех версиях игры: Gson и log4j.

| Файл | Что делает |
| --- | --- |
| `picture/PictureSettings.java` | Место и настройки картины: поля, константы (`SOURCE_*`, `FIT_*`, `MODE_*`, `FRAME_*`, `CANVAS_*`, старые `STYLE_*`), ключ источника, размеры в блоках, чтение и запись NBT через адаптер `Tag`. Версия наследует отсюда `PictureFrame`. |
| `picture/CanvasGeometry.java` | Геометрия картины: оси "координат стены", угол клетки рамки, рамка холста в мире, клетки света, стык картин в углу. Версия наследует отсюда `FrameGeometry`. |
| `ModConfig.java` | Настройки мода из `config/minepapers.json`. |
| `picture/MaterialStack.java` | Слот материала у стопки картин: сколько картин меняет клик и можно ли менять стопку. |
| `picture/MaterialSlots.java` | Предметы настраиваемой картины на сервере: клики по слотам материалов, Shift+клик, вставка материалов из конфига, сохранение настроек от клиента (блоки, ненужные виду, — игроку). Стопка предметов — класс версии: версия даёт адаптер `HolderMaterials` (пустая ли стопка, сколько в ней, копия, тот же ли предмет, слоты материалов, инвентарь игрока). |
| `picture/PictureTarget.java` | Что настраивает окно, одним числом для пакетов: id картины-сущности или слот картины-предмета в инвентаре игрока. |
| `picture/PictureConfig.java` | Настройки картины в виде JSON для копирования и вставки. Перевод названий предметов между версиями до 1.13 и после. |
| `picture/Links.java` | Поиск ссылок в описании. |

| `client/Covers.java` | Кэш последнего показанного кадра каждой картины на диске, по мирам и серверам: показывается сразу, когда чанк картины загружается снова. |
| `client/ImageStylizer.java` | Подготовка текстуры под холст: вписывание, пикселизация, постеризация, дизеринг. |
| `client/GifFrames.java` | Сборка кадров анимированного GIF в полные картинки. |
| `client/ImageSync.java` | Клиентская часть обмена картинками с сервером: подготовка и выкладывание, скачивание в кэш. |
| `client/ClientHost.java` | Адаптер: что клиентскому коду нужно от версии игры. |
| `server/ImageStore.java` | Серверная часть обмена картинками: приём, хранение в папке мира, раздача игрокам. |
| `server/ServerHost.java` | Адаптер: что серверному коду нужно от версии игры. |
| `network/SharedImage.java` | Формат картинки на сервере, SHA-1, размеры кусков в пакетах. |
| `client/PictureMesh.java` | Картина в мире целиком: холст, рамка, багет, картинка, пластина, плавный свет, свечение, значок NSFW, выбор слайда. Версия даёт только вывод вершин, свет клетки и смену текстуры. |
| `client/IconLayout.java` | Раскладка иконки настроенного предмета: холст, кольцо рамки, видимая часть миниатюры. |

Отличия версий:

- **1.7.10.** Предмет картины является `ItemBlock` блока `BlockPictureFrame`, рецепт и предмет лежат в пакете `block`. В пакете `block` есть классы для старых сохранений, где картины были блоками: `TileLegacyPicture` превращает такую картину в сущность, `BlockPictureFiller` убирает лишние части. Свет ставится своим невидимым блоком `BlockPictureLight`. Своё многострочное поле ввода `GuiTextArea`, потому что в 1.7.10 его нет.
- **1.12.2.** Код близок к 1.7.10 (имена MCP, метаданные предметов, старый OpenGL), но: предмет картины — обычный `Item` в пакете `item` (блока картины и классов старых сохранений нет), регистрация событиями `RegistryEvent`, пустая стопка — `ItemStack.EMPTY`, вершины — через `BufferBuilder`, состояние OpenGL — через `GlStateManager`. Свет — свой невидимый блок `BlockPictureLight` с силой в состоянии `level`. Настройки предмета — в NBT под ключом `MinePapersFrame`, как в 1.7.10. Иконку настроенной картины рисует `TileEntityItemStackRenderer` (`RenderPictureItem`): `ClientProxy` даёт настроенным картинам свою модель `RenderPictureItem.Model` со встроенным рендером, она же сообщает, где рисуется предмет (в инвентаре или в мире). Текстуры рамки и холста по умолчанию кладутся в атлас блоков (`FrameSkin.Events`). Поле `GuiTextArea` — как в 1.7.10. В ресурсах есть `pack.mcmeta` с форматом 3: без него Forge 1.12.2 считает мод ресурспаком старого формата и ищет словари под именами `en_US.lang`, а не `en_us.lang`. RetroFuturaGradle для среды разработки берёт Forge 14.23.5.2847; мод работает на нём и на всех более поздних сборках 1.12.2.
- **1.21.1.** Предмет и рецепт в пакете `item`. Настройки хранятся в компоненте предмета `minepapers:frame`. Свет ставится ванильным блоком `minecraft:light`. Подсказки окна сделаны ванильными `Tooltip`. Свои типы отрисовки в `client/PictureRenderTypes.java`. Место и настройки картины приходят клиенту ванильными данными сущности (`SynchedEntityData`), без данных спавна загрузчика. Всё, что зависит от загрузчика, общий код получает через `Platform` (пакеты, окно с данными для клиента, текущий сервер) и `client/ModClient` (события клиента). Загрузчики — тонкие обёртки: NeoForge — `neoforge/MinePapersNeoForge` и `MinePapersNeoForgeClient` (регистрация, пакеты, события); Fabric — `fabric/MinePapersFabric`, `MinePapersFabricClient` и два миксина, для которых у Fabric API нет событий: клики мышью до ванильной обработки (`MinecraftMixin`) и возврат материалов при крафте (`ResultSlotMixin`).
- **1.20.1** (то же дерево `modern/`, отличия размечены условиями `//?`). Настройки предмета — в его NBT под ключом `MinePapersFrame`, как в 1.7.10 (компонентов предметов до 1.20.5 нет). Пакеты — те же `ModPacket`, их передаёт канал загрузчика: у Forge — `SimpleChannel`, у Fabric — пакеты по `ResourceLocation`, обработчик переносится в главный поток. Окно рисуется прежними текстурами интерфейса (`widgets.png`, `tabs.png`, `beacon.png`): спрайтов интерфейса до 1.20.2 нет. Папки данных во множественном числе (`recipes`, `structures`, `tags/entity_types`) — их переименовывает сборка, ресурсы лежат в раскладке 1.21. У Forge в ресурсах узла есть `pack.mcmeta`: без него Forge 1.20.1 не подключает данные мода.
- **26.1.2, 26.2, 26.3 — Forge** (то же дерево, условия `//? if >=26.1`, `>=26.2`, `>=26.3`). Код движка — один на три версии: `modern/forge26/src` (Stonecutter его не обрабатывает, поэтому в нём нет условий; что в 26.x различается — клики и обводка блока — в общем `client/ForgeClientEvents` под `//? if forge && >=26.1`). Узлы `versions/26.*-forge` — только `gradle.properties` с версиями, сборка — `modern/forgegradle.gradle` (ForgeGradle 7, игра без обфускации). То, что в 26.x только переименовали (`ResourceLocation` → `Identifier`, `ClickType` → `ContainerInput`, методы окна `render*` → `extract*` и т.п.), Stonecutter заменяет сам (`modern/mc26.gradle`), в общем коде остаются имена 1.21; поэтому в ветках 26.x тоже пишется `GuiGraphics`. Рендер сущности и предмета с 26.1 не пишет в буферы сам, а отдаёт геометрию в `SubmitNodeCollector`: общий код рисует по-старому в `client/VertexSink`, а `client/Recorder` передаёт записанные вершины игре. Настроенную рамку рисует особый рендерер модели (`RenderPictureItem`, описание — `modern/src26/.../items/picture_frame.json`); своего события для его регистрации у Forge 26 нет, `MinePapersForgeClient` кладёт его в ванильный список. Сущность сохраняется через `ValueOutput` с прежними ключами, синхронизируемые настройки идут строкой SNBT (тега NBT в данных сущности больше нет). Игровые тесты — данные: функции регистрирует отдельный мод тестов `minepapers_tests` (`forge26/src/gametest`), описания `data/minepapers/test_instance` пишет сборка по методам `PictureGameTests`; запуск — `runGametestGameTestServer`.

## Общий код и адаптеры

Общий код не знает классов Minecraft. Всё, что зависит от версии, он получает через небольшие адаптеры. Версия реализует их у себя и подключает при запуске.

**ClientHost.** Подключается при запуске клиента (`ClientHost.install`). Даёт общему клиентскому коду:

- папку игры и папку `config/minepapers`;
- User-Agent для запросов в интернет;
- базовые цвета карт этой версии (для палитры карт; в разных версиях их разное число);
- признаки "есть соединение с сервером" и "сервер запущен в этом клиенте";
- имя текущего мира: папка одиночного мира или адрес сервера (по нему делится кэш кадров);
- загрузку кадра в видеопамять и его освобождение. Ссылка на текстуру у каждой версии своя: в 1.7.10 и 1.12.2 это номер текстуры OpenGL, в 1.21.1 это `ResourceLocation`. Общий код хранит её как `Object` и отдаёт обратно рендеру версии;
- отправку трёх клиентских пакетов обмена картинками.

`ClientHost.install` заодно регистрирует в ImageIO читатель WebP от TwelveMonkeys: сама ImageIO WebP не читает. Целиком библиотеки TwelveMonkeys весят ~500 КБ, поэтому задача `shrinkWebp` корневого `build.gradle` пропускает их через ProGuard по правилам из `common/proguard/webp.pro`. ProGuard оставляет только читатель WebP и то, что ему нужно (~90 КБ), даёт классам короткие имена и переносит их в пакет `com.grihail.minepapers.lib`. Так они не столкнутся с полной копией TwelveMonkeys из другого мода. Готовые классы попадают в jar вместе с ресурсами, одинаково в обеих версиях. Сам мод с TwelveMonkeys не компилируется: `ClientHost` создаёт читатель по имени `com.grihail.minepapers.lib.WebPImageReaderSpi`, которое задано в `common/proguard/webp.map`. Таблица старых и новых имён (для разбора стека из крашрепорта) - `build/webp/mapping.txt` подпроекта.

**ServerHost.** Подключается при запуске мода (`ServerImages.install`). Даёт `ImageStore`:

- папку текущего мира;
- настройки картины по измерению и номеру из `PictureTarget`;
- запись списка выложенных картинок в картину;
- отправку двух серверных пакетов.

Игрок и измерение передаются в `ImageStore` как `Object`. Общий код их только хранит и возвращает версии. У картины-предмета вместо измерения передаётся UUID игрока, в чьём инвентаре она лежит.

**PictureSettings.Tag.** Обёртка над NBT-тегом версии (`NbtTag`). Числа читаются и пишутся как int: обе версии умеют читать любое число тега как int. UUID в 1.7.10 и 1.12.2 хранится строкой, в 1.21.1 массивом чисел.

**Наследование.** `PictureFrame extends PictureSettings` и `FrameGeometry extends CanvasGeometry`. Поэтому код версии пишет `PictureFrame.FIT_COVER` или `FrameGeometry.normal(frame)`, хотя сами константы и методы лежат в общем коде.

Права игроков проверяет версия. `ImageStore` вызывается уже после проверки.

## Словари

Словари лежат в `common/lang`, по одному JSON на язык: `en_us.json`, `ru_ru.json`, `ja_jp.json`, `zh_cn.json`. Это единственный набор переводов для всех версий. Ключи во всех версиях одинаковые.

При сборке словари приводятся к формату версии:

| Версии | Файл в jar |
| --- | --- |
| 1.13 и новее | `en_us.json` без изменений |
| 1.11 - 1.12.2 | `en_us.lang` |
| до 1.11 | `en_US.lang` |

Формат `.lang` строится задачей `convertLang` в корневом `build.gradle`: строки `ключ=значение`, перенос строки внутри значения записывается как `\n`.

Перенос строки в JSON пишется обычным `\n`. Версия 1.21.1 переносит такие строки сама. Версии 1.7.10 и 1.12.2 получают в `.lang` буквальный `\n` и разбивают строку по нему в коде окна.

Названия предмета и сущности в 1.7.10 и 1.12.2 берутся по тем же ключам, что и в 1.21.1 (`item.minepapers.picture_frame`, `entity.minepapers.picture`). Для этого в них переопределены методы, которые возвращают названия.

Новый ключ добавляется во все четыре JSON.

## Данные и форматы

### Настройки картины в NBT

Одинаковы для всех версий (`PictureSettings`):

| Ключ | Значение |
| --- | --- |
| `FX`, `FY`, `FZ` | Клетка рамки. |
| `Facing` | Сторона, куда смотрит картина: 0 потолок, 1 пол, 2-5 стены. |
| `Rot` | Поворот на полу и потолке, 0-3. |
| `Surface` | Сдвиг от границы клетки до поверхности блока, от -1 до 0. |
| `Src` | Источник: 0 config/minepapers, 1 онлайн-папка (Яндекс Диск, Google Диск), 2 папка, 3 ссылка. |
| `Local`, `Url`, `Folder`, `ImageUrl` | Путь или ссылка для каждого источника. |
| `Interval` | Интервал слайдшоу в секундах. |
| `W`, `H`, `SizePx` | Размер холста и признак "в пикселях". |
| `OX`, `OY`, `PosPx` | Смещение холста и признак "в пикселях". |
| `Pad`, `PadPx` | Отступ картинки и признак "в пикселях". |
| `Zoom`, `ZoomPx` | Масштаб картинки (больше нуля - крупнее, меньше - мельче) и признак "в пикселях". |
| `IX`, `IY`, `ImagePx` | Сдвиг картинки внутри её области, вправо и вверх, и признак "в пикселях". |
| `Title`, `Desc` | Заголовок и описание. |
| `Owner`, `OwnerName` | Владелец приватной картины и его ник. |
| `Signer`, `SignerName` | Кто подписал картину и его ник. Ставит только сервер, снять нельзя. |
| `Nsfw` | Пометка NSFW (18+), 1 - помечена. |
| `Molding` | Ширина багета в пикселях. |
| `Sharp`, `MapPalette`, `Colors`, `Dither`, `DitherMode` | Резкие пиксели (1 - без полупрозрачности), палитра карт (1 - вместо числа цветов), число цветов (2-25), сила дизеринга в процентах и его вид (0 диффузный, 1 сеточный). У картин прежних версий вместо них `Style` (0 исходные цвета, 1-3 палитра карт без дизеринга, с ним и с мягким), при загрузке он переводится в тот же вид. |
| `Fit`, `PPB`, `Mode` | Вписывание, пикселей на блок, вид. Вид - сочетание рамки и холста: 0-3 - прежние виды (панель, рамка, граффити, пластина), 4-8 - новые сочетания (см. `PictureSettings.LOOK_FRAME`). |
| `GlowPart` | Что светится: 0 картинка с холстом (по умолчанию, ключа нет), 1 только рамка, 2 всё. |
| `Files` | Картинки на сервере: подряд идущие SHA-1 по 20 байт. |

Материалы пишет версия: `Border`, `Canvas`, `Glow` (id предмета для текстуры) и `BorderItem`, `CanvasItem`, `GlowItem` (сам предмет). В 1.7.10 и 1.12.2 есть ещё `BorderMeta`, `CanvasMeta`, `GlowMeta`.

Где хранятся настройки:

- **Сущность.** Место картины лежит прямо в её NBT, настройки в `Settings`, клетки поставленного света в `Lights`.
- **Предмет в 1.7.10, 1.12.2 и 1.20.1.** NBT предмета, ключ `MinePapersFrame`.
- **Предмет в 1.21.1.** Компонент `minepapers:frame`.

### Конфиг для копирования

Пример JSON, который кнопка копирования кладёт в буфер обмена:

```json
{
  "mod": "minepapers",
  "format": 1,
  "minecraft": "1.21.1",
  "title": "Водяной дракон",
  "description": "",
  "nsfw": false,
  "source": { "type": "yandex", "path": "https://disk.yandex.ru/d/...", "interval": 10 },
  "size": { "width": 2, "height": 2, "pixels": false },
  "offset": { "right": 0, "up": 0, "pixels": false },
  "padding": { "size": 0, "pixels": true },
  "zoom": { "size": 0, "pixels": true },
  "image": { "right": 0, "up": 0, "pixels": true },
  "fit": "cover",
  "glowPart": "picture",
  "look": "panel",
  "frame": "edges",
  "canvas": "block",
  "style": "map-soft-dither",
  "sharpPixels": true,
  "mapPalette": true,
  "colors": 6,
  "dither": 45,
  "ditherMode": "diffusion",
  "pixelsPerBlock": 128,
  "materials": {
    "frame": { "item": "minecraft:oak_planks" },
    "canvas": null,
    "glow": null
  }
}
```

- Значения пишутся словами: `config`, `yandex`, `folder`, `url`; `fill`, `contain`, `cover`, `none`, `scale-down`; `panel`, `frame`, `graffiti`, `plate`; `none`, `edges`, `molding` (рамка); `none`, `block`, `picture` (холст); `original`, `map`, `map-dither`, `map-soft-dither`. Вместо слова можно указать номер.
- `glowPart` - что светится: `picture`, `frame`, `all`.
- При `"frame": "molding"` поле `moldingWidth` - ширина багета в пикселях (если его нет - 2).
- `sharpPixels` выключает полупрозрачность; `mapPalette` - палитра карт вместо `colors`; `colors` (2-25), `dither` (0-100) и `ditherMode` (`diffusion`, `ordered`) - число цветов, сила и вид дизеринга. `style` - стиль цвета из прежних версий мода: для них пишется ближайший, а при вставке `colors` и `dither` главнее него.
- `look` - вид из прежних версий мода. Рядом с `frame` и `canvas` пишется ближайший к ним `look`, чтобы конфиг понимали и старые версии. При вставке `frame` и `canvas` главнее `look`.
- Если поля нет, при вставке оно не меняется.
- У материала `null` означает "обычный", то есть вынуть предмет из слота. Материал можно записать и короче: `"frame": "minecraft:gold_block"`.
- По полю `minecraft` мод понимает, в каких названиях записаны предметы.

### Файлы на диске

| Где | Что |
| --- | --- |
| `config/minepapers/` | Локальные картинки игрока. Папка создаётся при запуске. |
| `config/minepapers.json` | Настройки мода (см. [Настройки мода](../README.ru.md#настройки)). |
| `<папка игры>/minepapers-cache/` | Кэш картинок, скачанных с сервера, и подготовленных к выкладыванию. Имя файла - SHA-1 в hex. |
| `<папка игры>/minepapers-cache/covers/` | Последний показанный кадр каждой картины (`Covers`). Имя файла - SHA-1 мира, измерения и места картины. Кадры, которые не показывались 30 дней, удаляются. |
| `<папка мира>/minepapers/` | Картинки, выложенные на сервер. Имя файла - SHA-1 в hex. |

Файл картинки на сервере начинается с заголовка из 12 байт: `MPI1`, затем исходные ширина и высота картинки. Дальше идёт сам файл картинки. Исходный размер нужен, потому что большие картинки перед отправкой уменьшаются, а вписывание считается по исходному размеру. Предел веса картинки задаёт настройка `maxImageMb` (по умолчанию 16 МБ); клиент получает его от сервера при открытии окна картины.

## Сетевые пакеты

| Пакет | Направление | Что делает |
| --- | --- | --- |
| `PacketOpenFrame` | клиент -> сервер | Открыть окно настройки картины. |
| `PacketSaveFrame` | клиент -> сервер | Новые настройки картины. Список файлов на сервере и владельца клиент изменить не может, он только просит закрыть или открыть замок. |
| `PacketPasteMaterials` | клиент -> сервер | Какие предметы положить в слоты материалов при вставке конфига. |
| `PacketBreakPicture` | клиент -> сервер | Игрок начал ломать картину или доломал её. Сервер проверяет, что прошло достаточно времени. |
| `PacketOfferFiles` | клиент -> сервер | Список SHA-1 картинок для рамки. |
| `PacketHashes.Need` | сервер -> клиент | Пришли эти картинки. |
| `PacketFileChunk.Upload` | клиент -> сервер | Кусок выкладываемой картинки, до 30000 байт. |
| `PacketHashes.Request` | клиент -> сервер | Пришли мне эти картинки. |
| `PacketFileChunk` | сервер -> клиент | Кусок картинки, до 32 КБ. `total = -1` значит, что такой картинки на сервере нет. |

Скорость ограничена, чтобы не забивать канал. Клиент отправляет 2 куска за тик. Сервер отдаёт до 3 кусков за тик одному игроку и до 24 кусков за тик на всех.

В 1.7.10 и 1.12.2 обработчики пакетов работают в сетевом потоке, поэтому серверные пакеты ставят задачу в очередь `ServerImages.schedule`, и она выполняется в серверном потоке. В 1.21.1 обработчики сразу работают в нужном потоке.

## Как добавить новую версию игры

1. Современная версия (1.20+): добавить её с загрузчиками в блок `stonecutter` в `settings.gradle`, создать узел `modern/versions/<версия>-<загрузчик>` с `gradle.properties` (версии Java и зависимостей) и кодом загрузчика (по образцу соседнего узла), а различия версий в `modern/src` разметить условиями `//?`. Шаги 2-6 ниже — для старых версий.
   Старая версия: создать папку `<версия Minecraft>/<загрузчик>`, например `1.12.2/forge`, со своим `build.gradle`: плагин, версия Java, версия загрузчика.
2. Добавить её в список версий в `settings.gradle`.
3. Если нужен новый плагин сборки, объявить его в корневом `build.gradle` с `apply false`.
4. Перенести классы версии по образцу соседних папок. Реализовать адаптеры: `NbtTag`, `MinePapersClientHost`, `ServerImages` (как `ServerHost`). Унаследовать `PictureFrame` от `PictureSettings` и `FrameGeometry` от `CanvasGeometry`.
5. Подключить адаптеры при запуске: `ClientHost.install(...)` на клиенте и `ServerImages.install()` при старте мода.
6. Словари, текстуры и формат `.lang` подхватятся сами по версии из имени подпроекта.
7. Подключить игровые тесты: общие тесты версии и задачу запуска тестового сервера, добавленную в `gameTest` корневого проекта (см. `modern/*.gradle`). Если у версии нет фреймворка игровых тестов — тестовый мод, который прогоняет проверки при запуске выделенного сервера (см. `1.12.2/forge`).

Если код одинаков для двух и более версий и не обращается к API игры, он переносится в `common/java`. Копии из папок версий при этом удаляются.

## Правила проекта

- Весь текст, который видит игрок (словари, подписи в окне, подсказки, чат), пишется обычной пунктуацией: `-` вместо длинного тире, `x` вместо знака умножения, обычные кавычки, `...` вместо многоточия одним символом. Исключения - стрелки направления (↔ ↕ ◀ ▶ ▲ ▼) в подсказках числовых полей вкладки размера и точки "•" списка сервисов в подсказке онлайн-папки. В японском и китайском переводах можно использовать родную пунктуацию этих языков.
- Комментарии в коде пишутся на русском.
- Где возможно, используются ванильные механики: блоки света, звуки дерева, правила дропа, подсказки виджетов, ванильные текстуры окон.
- Код не страхуется заранее от всех возможных ошибок. Ограничения остаются там, где они задают правила игры (размер холста, место, разрешение) или защищают сервер от чужих клиентов (сервер принимает только те файлы, которые сам попросил, и не тяжелее `maxImageMb`). Остальные ошибки исправляются, когда проявляются.
- Заметные изменения записываются в [CHANGELOG.md](../CHANGELOG.md) в раздел `[Unreleased]`. При выпуске версии раздел получает её номер.

## Выпуск версии

Релизы загружаются на CurseForge через Upload API: workflow [curseforge.yml](../.github/workflows/curseforge.yml) собирает все версии, скрипт [curseforge_publish.py](../.github/scripts/curseforge_publish.py) загружает jar. Если проверка не прошла (тег, раздел CHANGELOG, jar, версии игры на CurseForge), не загружается ничего.

Один раз: создать проект на CurseForge, выпустить токен на [странице токенов](https://authors.curseforge.com/#/settings/api-tokens) и добавить его в репозиторий:

```
gh secret set CURSEFORGE_TOKEN
gh variable set CURSEFORGE_PROJECT_ID --body <ID проекта>
```

Выпуск:

1. Поднять `mod_version` в `gradle.properties` и переименовать раздел `[Unreleased]` в CHANGELOG.md в номер версии.
2. Закоммитить и запушить тег: `git tag v1.6.0`, `git push origin main v1.6.0`.

Версия с `alpha`, `beta` или `-rc` в номере выходит как альфа или бета, остальные - как релиз.

Actions -> Publish to CurseForge -> Run workflow запускает то же вручную: с `dry_run` (включён по умолчанию) только сборка и проверки. Если часть файлов не загрузилась, лог называет значение для поля `only`: запуск с тегом в `ref`, без `dry_run` и с этим `only` догружает только их. Обычный Re-run загрузил бы все файлы повторно.
